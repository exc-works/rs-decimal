# API compatibility matrix

Pinned baseline: `a8791208e2d15483cf652cd2814b74b0c1a84187`. PRs 01–13 implement the numerical core and all protocol entry points. Ecosystem APIs are covered by the user-selected PostgreSQL SQLx, Serde configuration, and exact validation adapters (PR 15). See the [declaration inventory](api-inventory.json) for complete Go signatures, source locations, and build conditions. See the [technical design](technical-design.md#api-compatibility-matrix) for statuses, fields, and acceptance rules.

PR 01 establishes delivery ownership and treatment; concrete Rust signatures, per-entry behavior, failure order, and test evidence are completed in the corresponding implementation PR. Entries marked “design pending” cannot count as compatible. Core entry points follow the [numerical contract](../testdata/upstream/docs/numeric-contract.md); decoding entry points must separately state null and failure-state rules.

## PR 03 behavior rules

- `Decimal::default()` is uninitialized zero. Explicit integer construction initializes the value and preserves the target scale. AppendPrec constructors preserve the integer's mathematical value and pad zeros. BigInt arguments are copied, and accessors return copies. Rust references exclude Go's nil BigInt argument; this is a type-level mapping difference.
- NewFromString exactly parses decimal/scientific notation under the Go contract, trims surrounding Unicode whitespace, and requires digits on both sides of a decimal point. The exponent is a signed 32-bit integer, and the absolute value of the final scale cannot exceed 131072. Parsed zero is normalized to initialized zero with scale=0. Failure returns InvalidFormat; MustFromString uses a typed panic with the same error.
- Negative explicit precision first panics with InvalidPrecision. Nonnegative precision within the native range is not universally subject to the parser's limit. Rust types constrain native signed/unsigned inputs.
- Clone/NewFromDecimal preserves initialization state and scale. Abs/Neg initializes uninitialized zero and preserves the scale of initialized values. Sign/Is* and comparisons leave inputs unchanged; nil is mathematically equal to zero.
- Cmp returns -1/0/1; Eq/Ord use mathematical value. Min/Max preserves the first operand's complete state on equality. Between includes both endpoints and does not automatically swap bounds. Extreme-scale comparison uses bit-length bounds first rather than unconditionally expanding powers of ten.
- Numerical inspection and comparison introduce no additional semantic errors; big-integer allocation remains limited by machine resources. Constants map to zero/one/ten/hundred constructors, without reassignable globals.
- NullDecimal::new sets valid=true and preserves the supplied Decimal. Its fields allow an inner value to remain present when valid=false.
- Complete string/Display formatting compatibility was verified in PR 10a.

## PR 04 behavior rules

- The seven modes have integer values Down=0, Up=1, Ceiling=2, HalfUp=3, HalfDown=4, HalfEven=5, and Unnecessary=6. `from_raw` uses an assertion panic for invalid values; typed APIs cannot receive invalid enum variants.
- Rescale/RescaleDown and WithPrec variants of Floor/Ceil/Truncate/Round first reject negative precision with an InvalidPrecision panic, then construct an initialized result at the target scale. Methods without arguments target scale=0. Unnecessary panics with RoundUnnecessary only when rounding is required.
- Rounding uses exact quotient/remainder arithmetic. At negative midpoints, HalfUp rounds away from zero, HalfDown toward zero, and HalfEven to an even coefficient. Floor rounds toward negative infinity; Ceil toward positive infinity.
- Shift exactly multiplies the value by 10^places. places=0 preserves scale and initializes nil. For a nonzero shift, a nonnegative target scale above i32::MAX panics with Overflow; a negative target scale becomes an integer coefficient with scale=0.
- StripTrailingZeros never reduces scale below zero; zero is normalized to initialized zero with scale=0. SignificantFigures uses an assertion panic for figures<=0 and does not pad zeros to reach the requested digit count. Zero retains its original scale and initializes nil.
- All arithmetic inputs remain unchanged. Independent Rust neighboring-value tests cover 22,736 rounding combinations. The Go oracle was extracted from independent upstream tests; see [PROVENANCE](../tools/go-oracle/PROVENANCE.md) for sources and changes.

## PR 05 behavior rules

- Add/Sub aligns exactly to max input scale. AddRaw/SubRaw changes the coefficient while preserving scale. SafeAdd/SafeSub and MustNonNegative use assertion panics for negative results; successful results are initialized.
- Default Mul/Quo scale is max input scale. MulExact uses the sum and first panics with Overflow if it exceeds i32::MAX, including for zero inputs. MulWithPrec does not inherit that intermediate-scale limit and rounds directly at the target scale. All rounding occurs only at the final target; inexact Unnecessary results panic with RoundUnnecessary.
- WithPrec first rejects negative precision with InvalidPrecision. Quo next rejects a zero divisor with DivideByZero, then returns zero directly at the target scale for a zero dividend. Nonzero division panics with Overflow when the scaling offset exceeds the native signed range.
- QuoRem truncates the quotient toward zero with scale=0. The remainder has max input scale and the dividend's sign. Mod returns the same remainder; Rust names it `r#mod`, with a `modulo` alias. A zero divisor panics with DivideByZero.
- Confirmed resource-behavior difference: baseline Go QuoRem aligns scales before checking a zero divisor. For `1 / (0 × 10^-isize::MAX)`, it may exhaust resources first. Rust checks the divisor before alignment, preserving the contract's typed DivideByZero panic while avoiding pointless allocation; both Mod entry points benefit too. This does not change numerical results, scale, or error category and is an allocation behavior that need not match. Extreme inputs run only in Rust regressions; verification does not require exhausting the Go process's resources.
- Power retains input scale and applies final HalfEven rounding. 0^0=1; negative powers of zero panic with DivideByZero. After stripping trailing zeros, ±1 is handled first. Other powers panic with Overflow when the absolute exponent times max(1,scale,coefficient bit length) exceeds i32::MAX, including an overflow-safe path for i64::MIN.
- IntPart truncates toward zero. Remainder returns the integer part and unscaled signed fractional coefficient. IsInteger/HasFraction uses no floating-point checks. Inputs remain unchanged and returned big integers are independently owned.

## PR 06 behavior rules

- NewFromFloat32/64 uses a pinned Ryu version to produce the shortest round-trip decimal at the original bit width, removes the formatter's extra .0, and parses exactly. Negative zero normalizes to initialized zero; non-finite input panics with InvalidFormat. Random bit patterns are compared individually against Go's shortest-text choice and scale.
- Float32/64 locates the binary grid directly from an exact integer ratio and rounds ties-to-even; f32 does not pass through f64. Subnormals and signed underflow zero are preserved. Overflow returns infinity with the same sign and exact=false; exact=true means mathematical equality only.
- NewFromBigRat accepts only rationals whose reduced denominators contain factors of 2 and 5 alone; otherwise it returns InvalidFormat. Output uses the minimum terminating scale. WithPrec first rejects negative precision, then rounds once to the target scale; inexact Unnecessary results panic with RoundUnnecessary. Valid Rust references exclude Go's nil rational argument; this type mapping provides no null-pointer entry point.
- BigInt/BigRat returns independent copies. Int64/Uint64 accepts only exact integers within range; otherwise it returns (0,false), without presenting truncated values as success. BitLen uses the coefficient's absolute value. MostSignificantBit returns 0 for zero and uses an assertion panic for negative input.
- Besides Go differential tests, an independent Python Fraction verifier checks the exact midpoint rounding cell containing each floating-point result, boundary parity, sign, overflow/underflow, and exact flags. It does not call production integer rounding.

## PR 07 behavior rules

Default Sqrt/ApproxRoot output scale is max(input scale, 20). WithPrec retains the requested scale and uses exact HalfEven midpoint tests. Every successful result is initialized and leaves inputs unchanged.

## PR 08 internal interval validation

Interval endpoints are independently owned BigInts normalized at the current positive binary scale. Fractions and multiplication/division round outward. Division accepts positive denominator intervals and selects extreme corners based on numerator sign. Integer multiplication swaps endpoints for negative multipliers. Certification succeeds only when HalfEven rounding of both endpoints of the entire interval agrees.
Ziv starts with 64 guard bits and doubles to 8192, while total working precision remains subject to the 131072-decimal-digit budget. Closure errors return immediately; budget exhaustion returns NoConvergence; output scale does not change across retries. This layer remains private. Temporary dead_code annotations were removed when PR 09 integrated it.
Exact-rational enclosure tests in `src/interval.rs` cover negative values, zero crossings, general and binary scales, multiplication/division, and unchanged inputs. `src/transcendental.rs` covers forced retries, exhaustion after eight attempts, early budget rejection, and error propagation.
