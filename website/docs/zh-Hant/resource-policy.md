# Playground 資源限制

瀏覽器 bridge 的允許範圍小於 Rust 程式庫。`BridgeError` 的 `category: "resource"`
表示達到 Playground 配額，不是數值程式庫錯誤。在限制內，方法名、參數順序和計算
結果保持 Rust 行為；核心程式庫沒有修改。

| 限制 | 目前值 |
| --- | --- |
| 十進位輸入 | 8192 個 UTF-8 位元組；尾數及指數展開後的係數最多 4096 位 |
| 儲存 scale 及輸入 scale 的絕對值 | 1000 個小數位 |
| 結果係數的保守估計 | 16384 位二進位數，最多 4933 位十進位數 |
| 二進位/BSON 和 ByteBuffer 輸入 | 65536 位元組 |
| 驗證規則/錯誤清單及訊息映射 | 64 項；每個字串 8192 位元組；JSON 傳輸 65536 位元組 |
| 驗證翻譯文字 | 翻譯前保守估計總計 65536 位元組 |
| 單個 Wasm 實例的呼叫次數 | 10000，包含 getter、快照和中繼資料讀取 |
| 非平凡根的 degree | 128 |
| 對數/指數輸出精度、輸入 scale、係數 | 128 位小數、256 位小數、4096 個二進位位 |
| 普通 exp 輸入絕對值 | 64（保留可證明捨入為零的負輸入快速路徑） |
| 建置產物的 Wasm 線性記憶體上限 | 64 MiB |

配置轉換檢查原始小數文字及解碼後的 JSON 字串；128 位整數變體在傳輸前
驗證精確的有符號或無符號範圍。通用 Serde 適配器保留其錯誤介面，並拒絕浮點 visitor。
SQL scan 在按核心規則去除外圍引號後檢查文字。驗證規則在建構前檢查小數參數，
翻譯前限制重複預留位置展開；欄位及插入參數始終按字面文字處理。
文字、參數及 JSON 解碼將來源輸入限制為 8192 位元組，並在修改接收者前檢查解碼後的
小數文字，包括 JSON 跳脫。JSON 原始數字位元組保持精確，不經過 JavaScript number。
YAML/XML 來源輸入最多 8192 位元組；核心數值解析前檢查已解碼的標量或元素文字，
包含跳脫、CDATA、YAML 底線正規化及浮點補零。YAML 標量最多 4096 個
十六進位數字字符，以保守限制進位整數分配。
二進位解碼在分配 BigInt 前限制實際係數位數和編碼中的 scale。BSON 字串遵循文字
限制；Decimal128 指數展開在核心解析前檢查。解碼預檢查失敗均保留接收者狀態。

Rust wrapper 在解析前檢查指數展開和 scale；精確乘法檢查 scale 之和，捨入乘法
檢查輸出 scale，兩者都在計算前檢查中間係數位數。加減法檢查對齊增長及進位，
除法在分配前檢查分子或分母的縮放。商餘數運算在零除數檢查後檢查對齊。冪運算
限制正規化後的中間精度、係數增長及倒數縮放；保留核心零值、正負 1 的快速路徑
及分配前的 Overflow。消耗型算術即使預檢查失敗也會消耗接收者。精確有理數轉換檢查約分後的分母因子及
係數增長，捨入有理數轉換在乘法前檢查分子縮放。建構有理數前先拒絕零分母。
格式化限制寬度（65536 位元組）、precision（1000）及定點係數增長。追加在修改前
檢查已有緩衝區長度加保守文字長度，可能拒絕實際剛好可容納的操作。
根運算在呼叫核心前限制縮放、Newton 冪及精確中點驗證的中間值。非平凡 degree
最多為 128；零、正負 1 和一次根保留快速路徑，仍須符合輸出精度限制。
對數和指數使用更嚴格的輸入及精度預算，以約束有理數約分和所有區間細化重試，
包括核心最多 8192 個保護位。exp 還限制普通輸入絕對值；足夠負且核心可證明
捨入為零的輸入保留安全快速路徑。
核心能在分配前拒絕的負精度及零除數保留
原有程式庫錯誤。rescale 及指定精度的捨入在分配十次冪前檢查目標 scale 和係數增長。shift
檢查結果的 scale 和係數增長；有效位數捨入預留可能的進位。如果核心能在分配前
回傳 shift 溢出，則保留該程式庫錯誤。因此連續呼叫不能繞過
單次限制生成無限增長的值，格式化輸出也受值的範圍約束。保守估計可能拒絕最終
結果較小的操作，例如與零相乘；這屬於 Playground 策略，不是核心程式庫規則。
若輸入沒有獨立觸及資源限制，錯誤語法、負 precision 和未知捨入模式仍由程式庫報告。

消耗所有權的方法即使因 Rust 資源檢查失敗，也會消耗接收者；借用參數保持不變。
耗盡呼叫預算後，除釋放物件外的匯出呼叫持續失敗，重新建立 JS facade 不會重置
預算；新建 Wasm 實例才會重置。

JS facade 在 wasm-bindgen 複製輸入前檢查字串和位元組陣列長度，Rust 在呼叫核心
程式庫或再次分配前重新檢查切片。直接呼叫原始 ABI 會先產生參數的臨時副本，但不能
取消產物的線性記憶體上限；runner 必須隱藏原始 ABI。這不等於 JavaScript 堆或整個
瀏覽器進程的硬記憶體配額。runner 已提供 Worker 終止、原始碼及輸出限制，以及網路隔離。

本地 Node 26 測量中，解析並讀取 4096 位係數及格式化 scale 為 1000 的值約需
1.2 ms，僅作為開發測量，不是延遲承諾。CI 記錄相同測量並驗證拒絕邊界。
開發 Wasm 產物約 196 KB，gzip 後約 73 KB；最終提交的準確大小、哈希和記憶體
上限以 `build.json` 為準。
