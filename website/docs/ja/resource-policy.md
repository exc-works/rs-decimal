# Playground のリソースポリシー

ブラウザーの bridge は、Rust ライブラリよりも意図的に狭い範囲で動作します。`category: "resource"` の `BridgeError` は playground の上限に達したことを示し、数値ライブラリのエラーではありません。制限内での Rust メソッド名、引数の順序、結果は変わりません。コアクレートも変更しません。

| 制限対象 | 現在の値 |
| --- | --- |
| 小数入力 | UTF-8 で 8192 バイト、仮数または展開後の係数で 4096 桁 |
| 保存スケールと入力スケールの絶対値 | 小数点以下 1000 桁 |
| 結果の係数の推定サイズ | 16384 ビット（最大 4933 十進桁） |
| バイナリ／BSON と ByteBuffer の入力 | 65536 バイト |
| 検証規則・エラーのリストとメッセージマップ | 64 項目、各文字列 8192 バイト、JSON 転送 65536 バイト |
| 検証メッセージの置換テキスト | 翻訳前の保守的な合計上限 65536 バイト |
| Wasm インスタンスへの呼び出し | getter、スナップショット、メタデータを含め 10000 回 |
| 非自明な累乗根の次数 | 128 |
| log/exp の出力精度、入力スケール、入力係数 | 128 桁、256 桁、4096 ビット |
| 通常の exp の入力絶対値 | 64（負の入力がゼロへ丸められることを証明できる高速経路は保持） |
| ビルドした Wasm の線形メモリー上限 | 64 MiB |

入力スケールと正の指数の展開は Rust の解析前に確認します。設定値の変換では元の小数テキストとデコード済み JSON 文字列を調べ、128 ビット整数のバリアントでは転送前に符号付き／符号なしの正確な範囲を強制します。汎用 Serde アダプターは固有のエラー形式を保持し、浮動小数点の visitor 入力を拒否します。

SQL の scan はコアと互換の方法で外側の引用符を除去してからテキストを調べます。検証では構築前に規則の小数引数を調べ、翻訳前に繰り返すプレースホルダー展開を制限します。フィールドと挿入した引数はリテラルテキストのままです。テキスト／パラメーター／JSON デコーダーは入力を 8192 バイトに制限し、変更前に JSON エスケープを含むデコード済み小数テキストを調べます。元の JSON 数値バイト列は正確に保ち、JavaScript number を通して解析しません。

バイナリのデコードでは BigInt の割り当て前に実際の係数ビット数と符号化されたスケールを制限します。YAML/XML のソースは 8192 バイトまでです。エスケープ、CDATA、YAML のアンダースコアの正規化、浮動小数点へのゼロ挿入を含むデコード済みスカラー／要素テキストを、コアの数値解析前に確認します。YAML の基数に応じたスカラー割り当ては、16 進数字文字の保守的な 4096 文字上限で制限します。BSON 文字列にはテキスト上限を適用し、Decimal128 の指数展開はコアの解析前に確認します。すべてのデコーダーの事前検査の失敗はレシーバーの状態を保持します。

正確な積ではスケールの合計、丸める積では出力スケールを調べます。どちらも乗算前に中間係数のビット数を制限します。加減算では桁揃えによる増大と桁上がり、除算では割り当て前に分子または分母のスケール調整を調べます。商と剰余では除数がゼロでないことを確認してから桁揃えを検査します。累乗は逆数のスケール調整も含め、正規化された中間スケールと係数の増大を制限します。コアのゼロ／単位値の高速経路と割り当て前の Overflow は保持します。所有権を取得する演算では、この事前検査が失敗してもレシーバーを消費します。

正確な有理数変換は約分後の分母の因数と係数の増大を調べます。丸める有理数変換は乗算前に分子のスケール調整を調べます。分母がゼロでないことの検証は有理数の構築前に行います。書式設定では幅（65536 バイト）、精度（1000）、固定小数点の係数増大を制限します。追記は変更前に既存のバッファーと保守的な小数テキストの上限を確認するため、実際にはちょうど収まる操作でも拒否される場合があります。

累乗根ではコアの呼び出し前に、スケール調整した値、Newton 法の累乗、正確な中間点の証明を制限します。非自明な次数は最大 128 です。ゼロ、単位値、次数 1 の高速経路は出力スケール上限内で利用できます。log/exp にはより厳しい入力と精度の上限を適用し、有理数の約分と区間の精密化のすべての再試行を制限します。コアの最大 8192 ガードビットも含みます。exp は通常の引数の絶対値も制限します。コアがゼロへ丸められると証明できる十分に負の入力は、安全な高速経路を保持します。負の精度やゼロ除算は、コアが割り当て前に拒否できる場合、元のエラーを保持します。

rescale は 10 の累乗を確保する前に要求スケールと保守的な増大見積もりを確認します。精度を指定する丸めも同じ検査を使います。shift は結果のスケールと係数増大、有効数字の丸めは桁上がりの可能性を調べます。Rust が割り当て前に返せるシフトの Overflow は保持します。そのため、受理された操作を繰り返しても係数や小数の書式出力が無制限に増大することはありません。保守的な事前検査では最終値が小さい操作（例えば一方がゼロの積）も拒否することがあります。この上限はコアライブラリの規則ではありません。通常の不正テキスト、負の精度、不明な丸めモードは、独立にリソース制限を超えない限りライブラリエラーを保持します。

消費するメソッドは Rust がリソース制限で拒否しても値を消費します。借用オペランドは変わりません。インスタンスごとの呼び出し上限に達すると、解放以外の公開呼び出しは失敗し続けます。別の JS ファサードを作ってもリセットされません。新しい Wasm インスタンスの開始がリセットの境界です。

JS ファサードも wasm-bindgen が引数をコピーする前に文字列長とバッファー長を確認します。Rust はコアの解析や追加の割り当て前に受け取ったスライスを再確認します。生の ABI を直接呼び出すと Rust の検査前に一時的な入力コピーを確保できますが、ビルド済みモジュールのメモリー上限は解除できません。runner はこの生の ABI を非公開にする必要があります。これは JavaScript ヒープやブラウザープロセス全体のメモリーの厳密な上限ではありません。runner は Worker の終了、ソースと出力の上限、ネットワーク隔離を強制します。

ローカルの Node 26 では 4096 桁の係数の解析と読み取り、およびスケール 1000 の値の書式設定に約 1.2 ms かかりました。開発時の参考値であり、レイテンシーの保証ではありません。CI は同じ測定を出力し、拒否の境界も確認します。開発時の Wasm 成果物は約 196 KB（gzip で 73 KB）でした。`build.json` に最終コミットの正確なサイズ、ハッシュ、メモリー上限を記録します。
