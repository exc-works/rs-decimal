# Playground 리소스 정책

브라우저 bridge는 Rust 라이브러리보다 의도적으로 좁은 범위에서 동작합니다. `category: "resource"`인 `BridgeError`는 playground 예산에 도달했음을 뜻하며 수치 라이브러리 오류가 아닙니다. 제한 안에서 Rust 메서드 이름, 매개변수 순서, 결과는 바뀌지 않습니다. 코어 크레이트도 수정하지 않습니다.

| 제한 대상 | 현재 값 |
| --- | --- |
| 소수 입력 | UTF-8 8192바이트, 가수/확장된 계수 4096자리 |
| 저장된 소수 자릿수와 입력 스케일 절댓값 | 소수 1000자리 |
| 예상 결과 계수 | 16384비트(최대 십진 4933자리) |
| 바이너리/BSON 및 ByteBuffer 입력 | 65536바이트 |
| 검증 규칙/오류 목록과 메시지 맵 | 64항목, 문자열당 8192바이트, JSON 전송 65536바이트 |
| 검증 메시지 치환 텍스트 | 번역 전 보수적인 총합 65536바이트 |
| Wasm 인스턴스 진입 호출 | getter, 스냅샷, 메타데이터를 포함한 10000회 |
| 비자명한 근의 차수 | 128 |
| log/exp 출력 정밀도, 입력 소수 자릿수, 입력 계수 | 128자리, 256자리, 4096비트 |
| 일반 exp 입력 절댓값 | 64(음수 입력이 0으로 반올림됨을 증명하는 빠른 경로는 유지) |
| 빌드된 Wasm 선형 메모리 최대값 | 64 MiB |

입력 스케일과 양의 지수 확장은 Rust 파싱 전에 검사합니다. 설정 변환은 원래 소수 텍스트와 디코딩된 JSON 문자열을 검사하며, 128비트 정수 변형은 전송 전에 정확한 부호 있는/없는 범위를 강제합니다. 일반 Serde 어댑터는 자체 오류 형식을 유지하고 부동소수점 visitor 입력을 거부합니다.

SQL scan은 코어와 호환되는 방식으로 바깥 따옴표를 제거한 후 텍스트를 검사합니다. 검증은 규칙의 소수 매개변수를 생성 전에 검사하고 번역 전에 반복적인 자리표시자 확장을 제한합니다. 필드와 삽입된 매개변수는 리터럴 텍스트를 유지합니다. 텍스트/매개변수/JSON 디코더는 소스를 8192바이트로 제한하고 JSON 이스케이프를 포함한 디코딩된 소수 텍스트를 변경 전에 검사합니다. 원래 JSON 숫자 바이트는 정확하게 유지하며 브라우저는 JavaScript number를 통해 파싱하지 않습니다.

바이너리 디코딩은 BigInt 할당 전에 실제 계수 비트 수와 인코딩된 소수 자릿수를 제한합니다. YAML/XML 소스는 8192바이트까지입니다. 디코딩된 스칼라/요소 텍스트는 코어 수치 파싱 전에 검사하며 이스케이프, CDATA, 밑줄 정규화, YAML 실수의 0 삽입도 포함합니다. YAML 스칼라의 진법별 정수 할당은 보수적인 4096개 16진수 숫자 문자 제한으로 제어합니다. BSON 문자열에는 텍스트 제한을 적용하며 Decimal128 지수 확장은 코어 파싱 전에 검사합니다. 모든 디코더의 사전 검사 실패는 수신 객체 상태를 유지합니다.

정확한 곱은 소수 자릿수의 합을, 반올림하는 곱은 출력 자릿수를 검사합니다. 둘 다 곱셈 전에 중간 계수 비트 수를 제한합니다. 덧셈/뺄셈은 자릿수 맞춤에 따른 증가와 자리 올림을 검사하고, 나눗셈은 할당 전에 분자 또는 분모의 스케일 조정을 검사합니다. 몫/나머지는 제수가 0인지 검사한 뒤 자릿수 맞춤을 검사합니다. 거듭제곱은 역수 스케일 조정을 포함해 정규화된 중간 자릿수와 계수 증가를 제한합니다. 코어의 0/단위 값 빠른 경로와 할당 전 Overflow는 유지합니다. 소유권을 가져가는 산술은 이 사전 검사가 실패해도 수신 객체를 소비합니다.

정확한 유리수 변환은 약분한 분모의 인수와 계수 증가를 검사합니다. 반올림 유리수 변환은 곱셈 전에 분자 스케일 조정을 검사합니다. 분모가 0이 아닌지 검증한 다음 유리수를 생성합니다. 서식은 폭(65536바이트), 정밀도(1000), 고정소수점 계수 증가를 제한합니다. 추가 연산은 변경 전에 기존 버퍼와 보수적인 소수 텍스트 크기 상한을 검사하므로 실제로는 딱 맞는 연산도 거부할 수 있습니다.

근 계산은 코어 호출 전에 스케일 조정 값, Newton 거듭제곱, 정확한 중간점 증명에 필요한 값을 제한합니다. 비자명한 차수는 최대 128입니다. 0, 단위 값, 차수 1의 빠른 경로는 출력 자릿수 예산 안에서 유지합니다. log/exp는 유리수 약분과 모든 구간 정밀화 재시도를 제한하도록 더 엄격한 입력/정밀도 예산을 적용하며 코어의 최대 8192 가드 비트도 포함합니다. exp는 일반 인수의 절댓값도 제한합니다. 코어가 0으로 반올림된다고 증명하는 충분히 음수인 입력은 안전한 빠른 경로를 유지합니다. 음수 정밀도와 0 제수는 코어가 할당 전에 거부할 수 있다면 원래 오류를 유지합니다.

rescale은 10의 거듭제곱을 할당하기 전에 요청한 자릿수와 보수적인 증가 추정을 검사합니다. 정밀도 지정 반올림도 같은 검사를 사용합니다. shift는 결과 자릿수와 계수 증가를 검사하고 유효 숫자 반올림은 가능한 자리 올림을 고려합니다. Rust가 할당 전에 반환할 수 있는 코어 shift Overflow는 유지합니다. 따라서 허용된 연산을 반복해도 계수나 서식화된 소수 문자열이 무제한으로 커질 수 없습니다. 보수적인 사전 검사는 최종 값이 더 작은 연산(예: 한쪽이 0인 곱)도 거부할 수 있습니다. 이 제한은 코어 라이브러리 규칙이 아닙니다. 일반적인 잘못된 텍스트, 음수 정밀도, 알 수 없는 반올림 방식은 별도로 리소스 경계를 넘지 않는다면 라이브러리 오류를 유지합니다.

소비 메서드는 Rust가 리소스 제한으로 거부해도 값을 소비합니다. 빌린 피연산자는 바뀌지 않습니다. 인스턴스 예산을 소진하면 해제를 제외한 모든 공개 호출이 계속 실패하며 다른 JS 파사드를 만들어도 초기화되지 않습니다. 새 Wasm 인스턴스를 시작해야 예산이 초기화됩니다.

JS 파사드도 wasm-bindgen이 인수를 복사하기 전에 문자열과 버퍼 길이를 검사합니다. Rust는 코어 파싱이나 추가 할당 전에 받은 슬라이스를 다시 검사합니다. 원시 ABI를 직접 호출하면 Rust 검사 전에 임시 입력 복사본을 할당할 수 있지만 빌드된 모듈의 메모리 최대값을 해제할 수는 없습니다. runner는 원시 ABI를 비공개로 유지해야 합니다. 이는 JavaScript 힙이나 브라우저 프로세스 메모리 전체에 대한 엄격한 할당량이 아닙니다. runner는 Worker 종료, 소스/출력 제한, 네트워크 격리를 강제합니다.

로컬 Node 26 실행에서 4096자리 계수의 파싱/읽기와 소수 자릿수 1000인 값의 서식화에 약 1.2 ms가 걸렸습니다. 개발 중 참고 측정이며 지연 시간 보장은 아닙니다. CI는 같은 측정을 출력하고 거부 경계를 검사합니다. 개발 Wasm 산출물은 약 196 KB(gzip 73 KB)였으며, `build.json`에 최종 커밋의 정확한 크기, 해시, 메모리 최대값을 기록합니다.
